# Upstream status-wake reconciliation

Date: 2026-09-06.

Upstream #3268 changes span classification so a `needs-decision`, `blocked`, `done`, or `failed` event is not hidden by a later routine append.

Upstream #3495 adds a main-drain backstop that resurfaces the newest captain-facing status when no newer branch outcome with matching status-file identity covers its captured endpoint.

This fork already had keyed OPEN DECISIONS folding and cursor-backed UNREAD STATUS presentation, so the port preserves those owners and adds the span endpoint and outcome receipt alongside them.

The fork keeps its existing three-column presentation manifest backward-compatible while accepting a fourth backstop-receipt column, and it records status provenance on new branch outcomes without rewriting legacy rows.

The upstream bounded outcome-index migration is deliberately omitted here because this fork's branch-outcome store has the earlier OMP contract; the backstop reads the validated provenance fields and treats legacy rows as uncovered.

Deduplication against a pre-cursor seen marker is identity-bound rather than timestamp-ordered.
Trusting such a marker records a `0@<device>:<inode>` binding in the marker's own endpoint sidecar, naming the status object it describes without claiming any of that object's bytes as classified.
A replaced status file therefore resurfaces matching text even when the replacement preserves the original timestamp, while an unchanged duplicate remains suppressed and a genuinely new append is still classified from byte zero.

Verification entry points are `tests/fm-watch-triage.test.sh`, `tests/fm-wake-drain-unread-status.test.sh`, `tests/fm-wake-drain-open-decisions.test.sh`, and `tests/fm-daemon.test.sh`.
